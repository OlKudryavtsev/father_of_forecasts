# v3.7.5 — Фоновый кэш шансов на победу и стабильное обновление PWA

## Скорость рейтинга

- Вкладка «Рейтинг» больше не запускает Monte-Carlo симуляцию во время HTTP-запроса.
- Шансы на единоличное первое место и «Расклады» хранятся в PostgreSQL в таблице `league_win_model_cache`.
- Бот пересчитывает кэш при запуске и далее раз в 3 минуты (настройка `LEAGUE_WIN_MODEL_AUTOSYNC_INTERVAL_SECONDS`).
- Перед повторным расчётом сравнивается сигнатура входных данных: если результаты, прогнозы, участники и живые долгосрочные ставки не изменились, готовый кэш остаётся без пересчёта.
- Пока первый расчёт выполняется после деплоя, рейтинг открывается сразу; вместо процента временно показывается «—», а в «Раскладах» — понятное сообщение об обновлении в фоне.
- В общей модели по умолчанию 6 000 прогонов. При необходимости можно задать переменную `LEAGUE_WIN_SIMULATION_RUNS` (минимум 2 000).

## PWA

- Устранён источник постоянной плашки «Доступна новая версия»: версия JavaScript, `app-version.json` и Service Worker теперь автоматически синхронизируются из `app/miniapp_frontend/package.json` перед production-сборкой.
- Backend для проверки обновления читает версию фактически собранного Mini App, а не отдельную потенциально рассинхронизированную строку.

## База данных

- Добавлена миграция `db/migrations/032_add_league_win_model_cache.sql`.
- При обычном запуске Docker/Railway таблица создаётся идемпотентно через SQLAlchemy до старта фонового воркера. Для контролируемых окружений рекомендуется применить миграцию отдельно.
